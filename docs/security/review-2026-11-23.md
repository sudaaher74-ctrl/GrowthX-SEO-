The most urgent issue is cross-tenant reuse of GitHub credentials. If the reviewed version is deployed, suspend credential reuse, check for connections made under unrelated workspaces, and compare the associated automation runs with GitHub audit records. Rotate affected grants. Confirm ownership of platform-admin accounts as a separate priority.

## Critical

### GitHub credentials can cross tenant boundaries

Repository connection looks up a saved token by GitHub owner across all projects. It checks what that token can push to and saves it under the requesting project. A project writer can therefore use another customer’s integration to read private source through automation and open pull requests wherever the reused token has write access. Disable global reuse, require an authorized connection belonging to the same project, and review existing connections and GitHub activity before re-enabling it. ### An unclaimed operator email can yield platform administration

Password signup immediately issues a session for the supplied email. The admin guard trusts that email and always adds a hard-coded owner address, even when the configured list excludes it. If an operator address is still unregistered, someone else can claim it, see the platform user directory and pause shared queues. Provision operators by immutable verified user ID, remove the built-in exception and confirm ownership of current operator accounts. ## High

### Google sign-in can inherit an account created by someone else

Google sign-in automatically reuses the password account matching the email. A pre-existing unverified signup keeps its original password after the mailbox owner signs in with Google. The original registrant retains access to future workspace data. Require verified email ownership before linking accounts, bind the provider subject to the account and resolve existing unverified links through an authenticated recovery flow. The content worker accepts the saved content directory and writes to the resulting filesystem path before validation. ### The engineer sandbox permits aliases to protected files

The sandbox applies its secret and protected-file rules to the requested name. Its later real-path check verifies only that the target is inside the repository. An in-repository symlink can therefore expose a protected file to the model or allow edits through a permitted name. Reject symlink traversal for file tools or apply the same read and write policies to every resolved target. Keep Git credentials out of checkout metadata. ### The CMS fallback uses a known encryption key

The Next.js route seals WordPress, Shopify and Webflow credentials with a built-in constant when no secret is supplied. The checked-in Compose frontend supplies none of the supported keys. Anyone who obtains a fallback token from that configuration can recover the underlying CMS credential. Remove the fallback, require a dedicated server key, and rotate credentials issued through the affected path. ### Copied CMS fallback tokens survive logout and role removal

The fallback accepts an encrypted browser-held credential on its own. ### Several outbound request paths can reach private-network services

Domain ownership verification uses ordinary Axios for a customer-controlled destination and follows redirects. The CMS handlers and webhook delivery resolve destinations before using a separate fetch connection. The rendered crawler caches DNS decisions while Chromium resolves the destination independently. Depending on host egress, these paths can reach internal services. Use connection-time public-address enforcement on every hop, fail closed on resolution errors, cap response sizes and isolate browser egress. ### GitHub browser credentials can survive an application account switch

The frontend restores a GitHub access token from a tab-wide session key and a GitHub App client secret from persistent local storage. ### OAuth callbacks lack browser-session binding

GitHub accepts a callback code without matching a one-time state to the initiating browser. Google sign-in also lacks a browser-bound state check. The Google data connector signs project and provider information, but its callback accepts that state without the originating session or a single-use record. These gaps permit account confusion or linking a consenting user's Google grant to the wrong workspace. Generate an expiring one-time server-side transaction per flow, bind it to the initiating browser and project, and consume it on callback. ## Medium

### Clients choose their own quota tier

The server derives the subscription tier from request headers and uses it to set website and crawl limits and gate white-label features. A customer can select the higher allowance. Derive entitlements from server-owned organization records and enforce quotas consistently across onboarding and direct API calls. ### Website registration checks the write role in the wrong workspace

Registration checks write access and quota in the caller’s default organization. For a supplied destination project, it checks only membership. A user with write access in one organization and viewer access in another can register a new website in the viewer-only project. Resolve the target organization first and perform the write-role and quota checks there. Autopilot checks the current website owner and subsequently upserts by domain and scope with an unconditional project reassignment. ### WebSocket origin and session checks stop short of protecting subscriptions

The gateway relies on CORS for origin filtering while accepting browser cookies, which default to SameSite=None in production. ## Verification and coverage

The review covered selected API controllers and service implementations, identity and tenant checks, CMS and GitHub integrations, crawler egress, the engineer sandbox, browser sessions, exports, deployment configuration and Git history. Severity reflects the affected data or privilege and the stated preconditions. A source finding establishes a code path. Production exposure and historical use require deployment and audit records.

Five existing Jest suites passed, covering 80 tests for authentication, JWT and CSRF guards, the engineer sandbox and AI secret redaction. Dependency advisory coverage remains open for both lockfiles. Registry access was blocked, and automatic approval review rejected sending the crawler dependency inventory to the public npm advisory service. The review did not exercise production hosts, use customer credentials, or determine whether anyone used these paths.
